# User Story 001: Setup Zitadel Identity Provider

## User Story

**As a** homelab administrator  
**I want** to configure Zitadel as the centralized identity provider with full automation  
**So that** all applications (OpenWebUI, Grafana, etc.) can use Single Sign-On (SSO) with zero manual configuration

## Acceptance Criteria

- [ ] Zitadel deploys from Git (Flux) with no manual UI configuration
- [ ] PostgreSQL database provisioned via CloudNativePG cluster
- [ ] Zitadel uses CNPG-generated database secrets automatically
- [ ] Master key stored as cluster-only Kubernetes Secret (not in Git)
- [ ] Initial admin user and Terraform service account created via bootstrap
- [ ] Terraform workspace CR manages Zitadel applications
- [ ] OpenWebUI OIDC application provisioned via Terraform
- [ ] OpenWebUI authenticates users via Zitadel SSO successfully
- [ ] Entire setup reproducible (can delete namespace and redeploy from Git)

## Technical Requirements

### Infrastructure Setup

**Location:** `clusters/homelab/tesselar-system/zitadel/`

**Cluster-Only Secrets (not in Git):**

- `zitadel-master-key` - Encryption master key (32 bytes)
- `zitadel-admin-credentials` - Initial admin password
- `zitadel-terraform-sa` - Service account token (auto-generated by bootstrap)

**Why cluster-only?** Zitadel is core infrastructure deployed across multiple clusters. Each cluster has different SOPS keys, so secrets cannot be encrypted in Git. They must be created manually per cluster (eventually automated).

### Database (CNPG)

CNPG automatically creates a secret `zitadel-postgres-app` with connection details:

- `host`, `port`, `username`, `password`, `dbname`

Zitadel HelmRelease must reference these secret keys for database configuration.

### Bootstrap Configuration

Zitadel HelmRelease includes bootstrap config to create:

1. **Organization:** "Tesselar"
2. **Admin User:** From `zitadel-admin-credentials` secret
3. **Terraform Service Account:** Machine user with key stored in secret

### Terraform Setup

Terraform workspace CR in `flux-system` namespace:

- Manages Zitadel OIDC applications
- Authenticates using bootstrapped service account
- Auto-applies changes (`approvePlan: auto`)
- Outputs app credentials to Kubernetes secrets

## Implementation Steps

1. **Setup Database & Secrets**

   - Create CNPG PostgreSQL cluster
   - Manually create `zitadel-master-key` and `zitadel-admin-credentials` secrets
   - Document secret creation for cluster replication

2. **Deploy Zitadel**

   - Configure HelmRelease to use CNPG secrets
   - Add bootstrap configuration
   - Deploy via Flux

3. **Configure Terraform**

   - Create Terraform workspace CR
   - Write provider and application resources
   - Test authentication

4. **Provision OpenWebUI**
   - Create OpenWebUI OIDC app via Terraform
   - Configure OpenWebUI deployment with credentials
   - Test SSO login flow

## Success Criteria

The story is complete when:

✅ Zitadel deploys from Git without manual steps  
✅ OpenWebUI SSO works end-to-end  
✅ Setup is reproducible (delete namespace → redeploy → works)
